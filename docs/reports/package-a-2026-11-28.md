## Summary of Changes

### Item 1 — Fixed & Extended `send_daily_digest()` (`0050_same_day_detection.sql`)
- **Today's cash:** now computes `SUM(daily_entries.amount_collected WHERE entry_date = today) + SUM(agent_payments.amount WHERE payment_date = today)` — includes both entry-linked (`source_entry_id IS NOT NULL`) and standalone (`source_entry_id IS NULL`) payments.
- **Total outstanding:** now computes the exact sum of `agent_outstanding()` across all agents (`daily_entries` unpaid − `agent_payments` − `write_offs` + `agent_damage_charges`), matching migration `0042`.
- **Terminology:** replaced banned `ရောင်းရငွေ` with `ကျသင့်ငွေ`, and `ဘူး` with `ဗူး` (no `ပုလင်း`, `ရောင်းရငွေ`, or `ရောင်းအား`).
- **Delivery policy:** sent to all active OM recipients (`om_recipients(null)`) unless `notify_prefs.alert_digest = false`. Recipients with `notify_prefs.mode = 'important'` are no longer skipped. Existing daily dedupe tag (`'digest-' || v_today`) is preserved.
- **Reconciliation section appended to body:**
  - Per-receiver cash totals for today (`coalesce(received_by, created_by)` across `daily_entries.amount_collected` + `agent_payments.amount`), compact `name amount` format.
  - Standalone payments today: count + total MMK (`source_entry_id IS NULL`).
  - Same-day edits and deletes today: counts from `audit_log` on `daily_entries`, `agent_payments`, and `expenses` (Yangon calendar day).
  - Handover mismatches today: receivers whose expected cash has no `cash_handovers` row (`မအပ်ရသေး`) or whose saved `received <> expected`; **omitted completely when none**.

### Item 2 — `HandoverPage` Blind Count (`src/pages/HandoverPage.tsx`, `src/lib/handoverCount.ts`)
- Unsaved employee rows start with an **empty** received-cash input (`''`) and a neutral `မစစ်ရသေး` badge — the expected cash amount is hidden until OM types the physically counted amount.
- Once a count is typed, the card immediately reveals `မျှော်မှန်းငွေ` alongside the difference (`ကိုက်ညီပါတယ်`, red `လိုနေပါတယ် …` when short, amber `ပိုနေပါတယ် …` when over).
- Clicking save on a blank unsaved input shows the validation error (`လက်ခံရငွေ မှန်ကန်စွာ ထည့်ပါ`) instead of coercing `''` to `0`.
- Top summary cards (`မျှော်မှန်း စုစုပေါင်း`, `ကွာခြားချက်`) aggregate only counted/saved rows (showing `—` when none are counted) so uncounted employees' expected totals never leak ahead of the blind count.
- Already-saved handovers keep their existing behaviour (input pre-filled with saved `received`, expected and difference visible, `expectedChanged` warning intact).
- Extracted pure testable helpers in `src/lib/handoverCount.ts` with 19 unit tests in `tests/unit/handoverCount.test.ts` and all new Burmese UI strings added to `src/lib/i18nDict.ts` in the same commit.

### Item 3 — Same-Day Anomaly Alerts (`0050_same_day_detection.sql`)
- Extended `run_data_quality_alerts()` with three same-day anomaly checks (in addition to keeping all existing checks from `0012` / `0015` / `0017` working):
  1. **Duplicate entries within 15 minutes** (same `agent_id`, `delivered_qty`, `returned_qty`, `amount_collected`), keyed per duplicate row (`dup_entry:<id>`, tag `dqdup-<id>`).
  2. **Negative held bottles** (agents with cumulative `SUM(delivered_qty - returned_qty) < 0` and activity today/yesterday), keyed per agent + latest entry date (`neg_held:<agent_id>:<date>`, tag `dqheld-<agent_id>-<date>`).
  3. **Extreme delivered quantity** (`delivered_qty > 2000`), keyed per entry (`high_qty:<id>`, tag `dqqty-<id>`).
- Scheduled a second `pg_cron` job `'wfms-data-quality-evening'` at **18:30 Yangon** (`'0 12 * * *'` UTC) while keeping the existing **08:30 Yangon** job (`'wfms-data-quality'`, `'0 2 * * *'` UTC). Per-issue `dq_seen` keys and notification tags guarantee the 18:30 and 08:30 runs never double-alert.
- Appended migration `0050` to `supabase/apply_all.sql` and added SQL test suite `tests/sql/23_same_day_detection.sql`.

## Assumptions
1. **Handover mismatch scope in `send_daily_digest()`:** Consistent with `HandoverPage.tsx` (`STAFF_ROLES = ['staff', 'manager', 'co_owner']`), an active `owner`-only profile who personally collected cash from an agent does not hand cash over to themselves, so a missing `cash_handovers` row is flagged for `staff` / `manager` / `co_owner` receivers (while any existing `cash_handovers` row with `received <> expected` is flagged regardless of role).
2. **Same-day anomaly window across 18:30 + 08:30 runs:** Checking `entry_date in (v_today, v_today - 1)` with per-issue `dq_seen` keys and per-issue notification tags ensures errors created before 18:30 are caught the same evening (and never double-alerted at 08:30 the next morning), while errors created after 18:30 (e.g., 20:00) are still caught at 08:30 instead of falling through the cracks.
