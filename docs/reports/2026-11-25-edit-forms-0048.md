## ၁။ ပြောင်းလဲထားသော ဖိုင်များနှင့် အသေးစိတ်

### Database (`supabase/migrations/0048_edit_entries_expenses.sql` + `supabase/apply_all.sql`)
1. **`expenses.change_reason`:** `expenses` ဇယားတွင် `change_reason text` column ထည့်သွင်းပြီး edit/delete reason ကို `audit_log` တွင် သိမ်းစေပါသည်။
2. **`entries_agent_immutable` (`BEFORE UPDATE` trigger on `daily_entries`):** Owner အပါအဝင် မည်သူမဆို `daily_entries.agent_id` ကို ပြောင်းလဲရန် ကြိုးစားပါက `agent_immutable` ဖြင့် DB မှ တိုက်ရိုက် ငြင်းပယ်ပါသည်။
3. **Atomic RPC `public.edit_daily_entry(...)`:**
   - `SECURITY DEFINER`, `search_path = public`, `EXECUTE` ကို `authenticated` သီးသန့်ပေးပြီး `PUBLIC` / `anon` ပိတ်ထားပါသည်။
   - DB ထဲတွင် တိုက်ရိုက် စစ်ဆေးသော စည်းမျဉ်းများ (UI ကို အားမကိုးပါ):
     - Active `is_staff_plus()` (pure agent နှင့် inactive account များကို `forbidden` ဖြင့် ပိတ်)
     - **Rule A (`0045`):** Owner / Manager / Co-owner သည် မည်သူ့ row မဆို ပြင်နိုင်ပြီး၊ staff သည် မိမိ `created_by` row ကိုသာ ပြင်နိုင် (`received_by` ဖြစ်ရုံဖြင့် အခြား staff ၏ row ကို ပြင်မရ)
     - **Same-day guard (SPEC rule 4):** Owner အပါအဝင် role အားလုံးအတွက် ဖန်တီးသည့် Asia/Yangon နေ့တစ်နေ့တည်းသာ ပြင်ခွင့် (`same_day_only`)
     - **Month lock (SPEC rule 6):** Owner အပါအဝင် role အားလုံးအတွက် ပိတ်ထားသောလတွင် ပြင်ခွင့်မရှိ (`month_locked`)
     - Input validation (`delivered_qty > 0`, `returned_qty >= 0`, `total_cash >= 0`, `change_reason` >= 2 chars)
   - `agent_id` နှင့် `unit_price` snapshot မပြောင်းဘဲ ငွေတစ်ကွက်တည်း (`today → old debt → overpayment`) ခွဲဝေမှုကို recompute လုပ်ပြီး `source_entry_id` linked `agent_payments` များကို transaction တစ်ခုတည်းဖြင့် atomic ပြန်ညှိပါသည်။
   - Linked payment များကို `daily_entries` update မတိုင်မီ ညှိပေးသည့်အတွက် `entries_before_write` ၏ `credit_limit` နှင့် `deposit_limit` စစ်ဆေးမှုက အမှန်တကယ် final balance အပေါ် စစ်ပြီး fail ဖြစ်ပါက transaction တစ်ခုလုံး rollback ဖြစ်ပါသည်။
   - OM က staff ၏ entry ကို ပြင်ပြီးနောက် staff မိမိ row ကို ထပ်ပြင်သည့် cross-role linked-payment RLS edge-case ကို ဖြေရှင်းထားပါသည်။
   - ငွေခွဲဝေမှု မပြောင်းဘဲ `received_by` သာ ပြောင်းပါက linked payment များကို in-place update လုပ်ပြီး delete/insert notification မထပ်စေပါ။
